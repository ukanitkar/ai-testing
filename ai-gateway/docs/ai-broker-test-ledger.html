ai-protect · AI Broker Windows E2E Suite

What each step does, and what it asks the elevated helper to do for it

Every step in run-e2e-suite.ps1 runs in one non-elevated window as umesh. Anything that needs Administrator — starting the service, reading another session's process owner, reading daemon.log under a SYSTEM-locked directory — crosses into a second window running run-e2e-suite-elevated-helper.ps1 and back. This is that boundary, made visible: the left side of every card is the step itself; the right side is exactly what it asked the elevated side to do.

STEP 0

Preflight — session, mock device plane, elevated helper

Read-only

Why

Two things silently invalidate every later step if wrong: umesh must be the active console session, not just logged in, and the mock device plane must actually be serving ai_broker.enabled: true — not merely reachable. A prior run's negative case (Step 11) can leave it disabled.

What / How

Kills stray processes and scratch directories a crashed prior run left behind, confirms the console session, and either starts the mock fresh or — if it's already up — checks what it's actually configured to serve before trusting it.

Ports

Upper limit

~3s mock health confirm · 15s helper reachability probe

Sandbox

No — operates on shared scratch state directly.

Messages

GET /endpoint/v1/config → checks settings.ai_broker.enabled
Elevated helper
sc-query Cheap reachability probe — confirms the helper window is alive before anything destructive begins. No side effect.

STEP 10

Negative case — broker.json protocol-version mismatch

Read-only

Why

BROKER_PROTOCOL_VERSION now lives on BrokerFile itself, so a mismatch is just a bad number written by hand — no rebuild, no hash-swapped binary, no elevation. It must refuse cleanly, drop the whole snapshot (not just the version field), and recover the instant a good one lands — and it must never risk the live service.

What / How

Spawns a fully isolated --control, writes protocol_version: 999 (must produce ready:false, empty agents[]), then protocol_version: 1 (must recover to ready:true).

Processes

ai-broker-mon.exe --control sandboxed ai-broker-mon.exe --llm-proxy retried per attempt

Ports

:18788 — deliberately not :8788

Upper limit

27s poll for recovery, 9×3s; ~20s internal budget per spawn attempt

Sandbox

Yes — own ZAX_DEMO_HOME. A negative test needs to feed the daemon a broken snapshot with zero chance of touching the real, already-running broker — which meant hand-reconstructing everything a real home already has: config.yaml, two distinct init.yaml files (per-user and the SDK's own bundled copy), a working directory, and a seeded credential.

Messages

broker.json{protocol_version:999,agents:[codex]} → status.json{ready:false, agents:[]}
broker.json{protocol_version:1} → status.json{ready:true}
Elevated helper
Not needed — fully self-contained, never touches the service.

STEP 14

--recover — the last destructive test

Destructive

Why

Reverses the bootstrap's edits, and deliberately proves the self-heal gap the runbook found: reconcile() — the only reap-and-respawn path — has exactly one call site, on_settings_received. The broker stays dead until a genuinely new settings frame arrives, never on a timer.

What / How

Dry-run first (must change nothing) → real run (kills both processes, strips codex's MCP entry, drops the cached JWT) → verify each claim → prove it stays dead for 90s with no new frame → restore a session-backed-up credential → force a new frame → poll the final state.

Processes

ai-broker-mon.exe ×2 toolhelp32 sweep ai-broker-mon.exe ×2 respawned

Ports

:8788 released, then rebound

Upper limit

90s proving the self-heal gap (9×10s); 70s for the respawn (14×5s); 60s for the final settle (20×3s)

Sandbox

No — operates on the broker's real home. The credential is backed up and restored around the destructive step; that's scaffolding for an unattended run, not isolation.

Messages

status.json overwritten · .codex\config.toml stripped, later re-merged
.credentials.json deleted, restored from backup · CONFIG_VERSION 3 → 4
Elevated helper
read-daemon-log Confirms the config-delta merge re-wired codex automatically once the broker respawned.
