AI Broker Windows E2E Suite — Step Order

Orchestrator: commands\run-e2e-suite.ps1 — run from a non-elevated PowerShell window as the console user, with run-e2e-suite-elevated-helper.ps1 already running in a separate elevated window.

Preflight

0Session, mock device plane, elevated helperread-only
Confirms the active console session is the expected user; starts the mock device plane on :8080 if not already reachable (60s heartbeat cadence); probes the elevated helper (sc-query) and aborts if it can't be reached.

Main sequence

1Fresh deploydestructive
Copies the freshly-built zscaler-ai-protect.exe / ai-broker-mon.exe onto the VM; hash-verifies both. Stops the service first so the copy isn't blocked by a file-in-use daemon/broker.
2Path B — SYSTEM service crosses the privilege boundaryread-only
Starts the service; greps daemon.log for the actual CreateProcessAsUser session crossing and the first status.json … ready.
3Privilege-drop ownership verificationread-only
Via the elevated helper's psinfo: confirms the daemon stays SYSTEM in session 0, and both broker processes run as the console user. The single most important fact this whole suite checks.
4TLS + per-install-token, liveread-only
Probes the live --llm-proxy on :8788: right token (expect not 401), wrong token (expect 401), missing token (expect 401), plain http:// (expect refused, no plaintext fallback).
5Unit suites, Windowsread-only
cargo test -p ai-warden --lib, cargo test -p ai-broker-mon, then the 9 elevation-gated tests (need SeRestorePrivilege) via the elevated helper's cargo-test-elevated action.
6secure_file owner-only DACLread-only
phase-a-acl.ps1 — ACL/owner spot-check on llm-proxy.token, .credentials.json, mitm-ca-key.pem, run as the console user on purpose (owner gets READ_CONTROL for free).
7Credential refresh, liveread-only
phase-b-cred-watcher.ps1 — ages the cached user-JWT sidecar to flip credential_requested, confirms the daemon notices and rewrites broker.json.
8Config-delta apply, livedestructive
phase-b-config-apply.ps1 — exercises the Windows ownership-reassignment write path (SetSecurityInfo); also proves a hostile delta naming .ssh/authorized_keys is refused. Backs up/restores the real .codex\config.toml itself.
9MCP leg — --mcp-server stdio relayread-only
Drives ai-broker-mon --mcp-server directly over newline-JSON-RPC stdio, standing in for an agent (Codex isn't installed on the VM). Runs under a 60s watchdog job — a hang itself counts as a finding (likely interactive OIDC on a stale cached credential).
10Negative case — broker.json protocol-version mismatchread-only
phase-c-protocol-mismatch.ps1 — hand-writes a bad protocol_version into a throwaway sandboxed --control process (own scratch home); confirms status.json reports ready:false and drops the whole snapshot, not just the version field. Deliberately outside the -SkipDestructive gate — never touches the live service.
Everything below only runs when -SkipDestructive is not passed.
11ai_broker.enabled=false transitiondestructive
phase-c-negative-setup.ps1 / phase-c-negative-flip.ps1 — flips the toggle on a live broker, confirms it's reaped and stopped; restores enabled=1 and polls up to 90s for the daemon's heartbeat to respawn it.
12Parent-death watchdogdestructive
phase-c-watchdog.ps1 — kills only --control; confirms the --llm-proxy child notices and exits within seconds. Restarts the service afterward.
13Graceful proxy shutdowndestructive
Stop/start cycle on the service; confirms port 8788 releases cleanly on stop and rebinds successfully on start (proof the previous child didn't orphan it).
14--recover — stray-process cleanup + config stripdestructive · last
phase-d-recover.ps1 — dry-run first (must change nothing), then the real run: kills both broker processes, strips Codex's [mcp_servers.zax] entry, then forces a fresh settings frame so the daemon respawns and re-wires the agent's config automatically.

Not run automatically

Negative case — nobody logged onmanual only
Needs a real RDP logoff of the running session. Run by hand: phase-e-nobody-setup2.ps1 (elevated) → log off → phase-e-nobody-check2.ps1 after logging back in. This is the path that surfaced finding D — a permanent SYSTEM-context zombie broker that never self-heals.
Reboot-survival checkopt-in: -IncludeReboot
Restarts the VM the script is running on. Off by default; follow up with phase-b-prep.ps1 then phase-b-verify.ps1 after it comes back.
